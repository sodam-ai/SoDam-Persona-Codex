# Development, testing and delivery
## Authority and preservation
Inspect the checkout, branch, uncommitted changes and remote before work. SoDam-Persona is upstream; SoDam-Persona-Codex is the Codex port. Verify URLs, not just remote names. Do not automatically change remotes, reset, force-push or delete existing changes.

```powershell
git status --short
git branch --show-current
git remote -v
```

## Source checks
CI uses Node.js 20. No external npm dependencies are required. Pandoc is needed only for document generation and checking.

```powershell
node validate.mjs
node --test test-hooks.mjs test-validator.mjs test-supplemental.mjs test-diagnose.mjs test-evaluate.mjs test-docs.mjs
node build-docs.mjs
node check-docs.mjs
```

Document checks compare visible text and bilingual heading structure. Translation meaning, accessibility and actual visual review are separate.

## Actual response tests
The command below sends one fixed fixture into a fresh temporary Codex conversation. It consumes signed-in Codex usage. User config is not loaded and candidate instructions are supplied explicitly; this is not an installed-hook integration test. It tests responses, not actual drawing edits or other domain operations.

```powershell
node evaluate.mjs --list
node evaluate.mjs --execute --case R42-positive --out ./evaluation-results/run-01
```

Each of the 270 IDs can be run separately. Existing records are not overwritten. Results contain timestamps, prompt hash, actual response, execution status and role-selection assessment. CLI errors, timeouts and invalid JSON remain failures. A selection pass is not a quality pass. Review whether reason/answer apply actual specialist criteria; also test natural-language indicators, JSON exceptions and automatic installed hooks in separate fresh conversations. Separate original outputs from review notes. Evaluation records may contain private information and must not be committed.

## Installation diagnosis and publication
The two migrated skills generated by Codex 0.160.1 from the original `create/edit` commands are accepted only when byte-identical to source-derived reconstruction. The extra directory is never broadly ignored: altered or unknown additional files remain blocked. If another Codex version changes the generation format, verify it before updating the diagnostic tool.

Use `node diagnose.mjs --json` or `--home <actual Codex home>` separately for CLI/Desktop. Caches with different version, content or registration are not executed. Unsupported cache layouts fail as unverified. Byte hashes also detect newline differences. Do not invent installation paths or edit config automatically.

Before delivery, inspect manifests, README, verification results, licensing, secrets and diffs. Use a tested work-branch PR instead of pushing directly to the default branch. Publication, Release and installation updates are separate steps. Editing this project does not update installed files or existing conversations. Do not distribute CHECKPOINT.md or private evaluation records. Legal interpretations and unverified rights require legal/professional review.
